# Requirement-to-feature checklist

Status: working initial application. The major workflows persist records, calculate results and expose source drilldowns. No original accounting or hospital reports were supplied; hospital-specific interpretations remain unvalidated. This checklist deliberately distinguishes implemented functions from additional work.

| Specification area | Delivered | Prerequisites / limits |
|---|---|---|
| Organisation and flexibility | Four initial branches; separate entity master; dynamic departments, cost centres, accounts, banks, vendors, panels, employees, consultants; versioned settings/rules | Real entities and account categories require reviewed configuration; categories are editable masters, statement category vocabulary is defined |
| Core principles | Decimal calculations; separate accounting, operations and cash; null missing values; authoritative journals or TB, never both added | Completeness is an explicit reviewed attestation, not an automated audit |
| Ingestion | CSV/XLSX, all worksheets, header selection, field mappings, versioned profiles, preview, rejects, exclusion reasons, hashes, overlap replace/retain, reprocess and rollback | Legacy XLS must be converted; source-specific formulas and report totals need actual-file validation; no automatic financial column inference |
| Auditability | Immutable originals/files, inactive superseded records, allocations, maker/reviewer proposals and audit log; scoped access | SQLite is an application audit store, not a tamper-proof external/WORM archive; no signed evidence attachments |
| Executive review | Accounting revenue, expenses, EBITDA/net result where supported, cash snapshots, AR/AP, stock, debt; period/source/coverage cards, comparisons and source IDs | No universal alert thresholds; configure materiality; no audited certification |
| Revenue controls | Final bill registers, service detail, pharmacy, revenue/accounting bridge, unbilled activity, discount/refund exceptions, tariff comparisons, discharge/bed-day economics | Package inclusion and service-cost overlap stay unresolved; no automated patient-level causal attribution or marketing ROI |
| Claims/collections | Lifecycle history, latest claim status, approvals vs receipts separation, approved deductions informational, due dates/ageing, partial/combined allocations, advances/refunds, credits/write-offs, opening rollforward | Actual payer terms/deadlines and refund authority must be supplied; opening snapshots use explicit scope/cutoff; no messages sent |
| Procurement/payables | PO/GRN/invoice registers, quantity/rate/amount three-way comparison, supplier liability, credits, settlements/advances, opening rollforward, proposed priorities and approved-vendor alerts | No execution of payments; retention is retained as source information, not automatically netted; complex multi-line PO matching needs further allocation support |
| Bank/cash/treasury | Movement/balance registers, rollforward checks, exact-reference suggestions with ambiguity, independently reviewed signed partial matches, residuals, 13-week base/delayed/stress schedules | Cash is latest supplied snapshot and may be stale; complete cash-flow accounting bridge unavailable; no bank connection; scenario settings explicitly supplied |
| Expenses/payroll/contracts | Expense/payroll/consultant registers, incurred/paid/unpaid, explicit fixed/percentage/per-procedure bases, exclusions/deductions/ceilings, effective dates; shared-cost driver allocations with paise reconciliation | No payroll processing, statutory calculation or automatic journal posting; multi-branch pools hidden when branch permissions cannot support full denominator |
| Inventory/pharmacy | Signed opening/movement rollforward per store/item/batch, recorded cost, physical count differences, transfer check, expiry exposure, Main/Secondary pharmacy known-cost profit and missing cost coverage | No inferred MRP cost, FIFO/weighted-average cost engine, reorder optimisation or automated batch costing; supplies must use reviewed signed costs |
| Assets/capex/debt | Asset register, recorded carrying value, optional configured straight-line estimate, capex variance; entity/branch loan movements, separate principal/interest, repayment schedules | Lease/rent/deposits can be tracked as expenses/assets/commitments; dedicated lease accounting, covenant ratio engine and capex approval lifecycle remain additional work |
| Statutory | Liability/payment/credit register, due dates, challan/evidence, outstanding schedule | No legal rates, tax computation, filing, or invented dates; due dates supplied by authorised finance |
| Profitability/statements | Categorised GL P&L or compatible TB movements; balance sheet when supported/reconciled; departmental partial contribution; accounting/operational bridge | Branch sums labelled aggregation; elimination rules/related-party sources retained but consolidated statements not implemented; cash-flow statement and current/quick/ROCE/DSCR ratios not implemented |
| Hospital economics | Revenue per unique discharge cohort, validated bed-day occupancy, departmental eligible contribution; explicit scenario break-even volume | Detailed equipment ROI, payer-normalised cohorts, occupancy-linked fixed-cost absorption and marketing causal attribution remain additional work |
| Budget/scenarios | Monthly branch/entity/category journal actual vs budget and percentage variance; explicit volume/price/deduction/cost assumptions, contribution, collections and break-even; separate cash forecast assumptions | Scenario assumptions do not change actuals; contribution excludes unstated costs; no optimisation, full balance-sheet scenario model or TB-based budget bridge |
| Financial gaps | Numerical/missing-data exceptions, expected/observed, overlapping exposure warning, evidence IDs, severity, owner/due/status/resolution | Review items are not proven losses; some advanced controls require additional configured sources/rules |
| Month-end/reports | Persistent checklist/ownership/evidence, independent signoff, locks/reopen proposals, late-period checks, immutable issued report versions and management exports | No PDF report designer or automated delivery; issued snapshots accessible via API, current CSV/XLSX management pack via UI |
| UX | Responsive thirteen-module interface, filters, search, saved views, CSV/XLSX, details, source trace, plain-language metric definitions, empty/unknown states | Advanced rule configuration uses reviewed JSON forms; additional simplification may be useful for daily operators |
| Privacy/permissions | Authenticated APIs, branch+register role enforcement, restricted payroll, PBKDF2 passwords, hashed sessions, protected writes, HTTPS cookie option, no patient access logs | No SSO/MFA or managed organisation directory; temporary tunnel is a preview, not permanent hospital hosting |
| Architecture/delivery | FastAPI/SQLite, pinned dependencies, local deterministic engine, templates, tests, browser screenshots, backup/restore, reusable cloud startup instructions | Single-instance SQLite deployment; no external ERP/bank integration or AI layer |

## Validation evidence

Run `bash scripts/install.sh` to install pinned dependencies, check package consistency and execute the suite. Tests use disposable databases and synthetic fixtures. The suite covers real/demo separation, accounting authority, partial and combined allocations, overpayment protections, refunds/credits, bank ambiguity/partial matches, inventory/cost unknowns, scoped debt, contract bases, import dedup/overlap/reprocess/rollback, period locks/reopen/report versions, forecast dedup, snapshots, cash-transfer/loan separation, budget/scenario calculations, allocation totals/filter stability, identifier formatting, permission/export consistency, backup restore and all thirteen browser modules.

Real-source reconciliation is outstanding because no real source files were attached. No blanket claim of accounting completeness or full advanced feature delivery is made.
